## 2. Finding: LangChain v1 has converged on All-Might's shape

`import langchain` now exposes **exactly three** names:

```python
['agents', 'chat_models', 'tools']
```

The `chains` / `memory` / `initialize_agent` era is gone. The single
entry point is `create_agent`, and every cross-cutting behaviour is a
**middleware**. This is the same architectural instinct as All-Might's
plugin/hook layer — horizontal concerns composed onto a core loop
rather than inherited into it. The difference is the mount point:
LangChain mounts onto its own runtime, All-Might mounts onto somebody
else's CLI.

The observed middleware stack, read off a real traceback:

```
FilesystemMiddleware → SubAgentMiddleware → SummarizationMiddleware
  → AnthropicPromptCachingMiddleware → MemoryMiddleware → model
```

### `deepagents` is the genuine competitor, and it is closer than expected

`create_deep_agent()` takes these parameters (verified by
`inspect.signature`):

```
model, tools, system_prompt, middleware, subagents, skills, memory,
permissions, backend, interrupt_on, response_format, state_schema,
context_schema, checkpointer, store, debug, name, cache
```

Translated into All-Might's vocabulary:

| deepagents | All-Might |
|---|---|
| `subagents=[SubAgent(...)]` | `personalities/<name>/` |
| `SubAgent.system_prompt` | `ROLE.md` |
| `SubAgent.skills: list[str]` | per-personality `skills/` slot |
| `SubAgent.permissions` | (no equivalent) |
| `memory=["AGENTS.md"]` | `MEMORY.md` (L1) |
| `backend=FilesystemBackend` | the project workspace |
| `HarnessProfile` | capability `TEMPLATE` |
| `RubricMiddleware` | **(no equivalent)** |
| `checkpointer` | (delegated to the host CLI) |

**The headline**: `MemoryMiddleware.__doc__` reads —

> "Middleware for loading agent memory from **`AGENTS.md` files**.
> Loads memory content from configured sources and injects into the
> system prompt."

LangChain's own agent harness has independently landed on
**markdown-file memory, injected into the system prompt, edited by the
agent via `edit_file`**. That is All-Might's L1 mechanism, arrived at
by a team with vastly more resources and no knowledge of this project.

This is the strongest validation the "markdown camp" call has received
in six passes — and simultaneously the most serious challenge, because
it means the idea is no longer differentiating.

## 3. Finding: the per-role memory story is convention, not structure

`trial1_store.py` result — `BaseStore` exposes:

```
get / put / search / delete / list_namespaces  (+ async, + ttl_config)
```

Namespaces are tuples, so per-role scoping is expressible:

```python
store.put(("memories", "stdcell_owner", "understanding"), "drive_strength", {...})
store.put(("memories", "pll_owner",     "understanding"), "lock_time",      {...})
```

`list_namespaces(prefix=("memories",))` correctly returned the three
distinct role namespaces, and `search(("memories","stdcell_owner"))`
correctly returned only that role's 2 items.

**But** — `search(("memories",))` returned **all 3 items across both
roles**. Isolation is a *naming discipline*, not a boundary. Nothing in
the type system, and nothing at runtime, prevents a tool from reading
across roles. All-Might's isolation is a directory tree, which fails
closed; LangGraph's is a tuple prefix, which fails open.

### Silent degradation found in `Store.search(query=...)`

```python
store.search(("memories","stdcell_owner"), query="timing violation", limit=3)
# → returns 2 items, score: None on every one
```

With no embedding index configured, the semantic `query=` argument is
**silently ignored** — no exception, no warning. The call returns the
namespace's contents in insertion order with `score=None`, which is
indistinguishable from a working semantic search that happened to rank
them that way. This is precisely the failure class All-Might's
heartbeat telemetry exists to catch (`fired` with `—` injected). Worth
recording as an argument *for* the T1/T2 heartbeat investment.

Also confirmed: `langgraph.store.{postgres,sqlite,file}` are **not** in
the core package — durable storage is a separate install. Out of the
box, `InMemoryStore` loses everything on process exit.

## 4. Finding: it runs, and the token bill is visible

`trial3_run.py` executed a full agent turn:

```
HumanMessage: 'Record that U123 fails setup.'
AIMessage:    tool_calls=['write_file']
ToolMessage:  'Updated file /notes/finding.md'
AIMessage:    'Recorded the finding to notes/finding.md.'
```

Tools auto-provisioned:
`['ls','read_file','write_file','edit_file','delete','glob','grep','task']`
(`task` is the subagent-delegation tool.)

Files genuinely landed on the real filesystem — `AGENTS.md` (139 B) and
the newly written `notes/finding.md` (42 B), both plain markdown. The
`AGENTS.md` sentinel string was confirmed present in the assembled
system prompt. Checkpointer recorded **7 checkpoints** for this 2-turn
run and `get_state_history` replayed them.

So: the machinery is real, it works, and it is pleasant.

### The measured cost

| Surface | Size | When it is paid |
|---|---|---|
| `deepagents` `MemoryMiddleware` guidelines | **5,120 chars ≈ 1,280 tokens** | **every model call** |
| Total system prompt for one 139-byte memory file | **5,428 chars** | every model call |
| All-Might `ROUTING_PREAMBLE` | **549 chars ≈ 137 tokens** | only on routed command bodies |

A 139-byte memory file cost 5,428 characters of system prompt — a
**39× overhead ratio**. The bulk is a hard-coded English essay telling
the model when to remember and when not to (`**When to update
memories:**`, `**When to NOT update memories:**`, three worked
examples, credential-handling warnings).

That essay is not configurable per-role and is not lazily loaded. It is
the same "meta-cognition instructions" pattern that All-Might's *Skill
/ Command Body Style Guide* rejects on sight:

> Anti-patterns (rejected on sight): Meta-cognition instructions
> ("first reflect on what you noticed, then list candidates, then
> filter...") — capable models already do this; weak models will
> mechanise it into noise.

For an air-gapped deployment on a Haiku-class model, paying 1,280
tokens per turn for that essay is a material regression, not a feature.

## 4b. The buried lede — `deepagents-code` (`dcode`)

The hypothesis named LangChain/LangGraph/LangSmith. Those turn out to
be the *wrong* thing to worry about. The thing to worry about is
`deepagents-code` **0.1.56, uploaded 2026-08-14 — the day before this
pass**. It self-describes as:

> "a pre-built coding agent in your terminal — **similar to Claude Code
> or Cursor** — powered by any LLM that supports tool calling."

Installed via `curl -LsSf https://langch.in/dcode | bash`. Textual TUI.
223 Python modules. It has `hooks/` (23 modules, loading
`{project}/.deepagents/hooks.json` then `~/.deepagents/hooks.json`),
`plugins/` with an MCP adapter, `skills/` with a trust store, sessions
persisted via `AsyncSqliteSaver`, and CLI verbs `agents skills plugins
mcp threads tools config auth doctor update install`.

### Per-agent identity — structurally a personality

```
~/.deepagents/<agent_name>/AGENTS.md     # that agent's long-term memory
~/.deepagents/<agent_name>/skills/       # that agent's skills
~/.deepagents/<agent_name>/agents/       # that agent's subagent definitions
```

Selected with `dcode --agent NAME`. That is **role = name + prompt +
own memory file + own skills dir** — All-Might's personality minus
capability composition, minus the workspace/vector layer, and
**user-global (`~`) rather than per-project**.

### Three independent reinventions of All-Might rules

1. **Progressive disclosure = L2 TOC.** `SkillsMiddleware` injects a
   *name + description* list into the system prompt and tells the model
   to read the full `SKILL.md` only on demand. Captured verbatim from
   a real run:

   > "Skills follow a **progressive disclosure** pattern - you see their
   > name and description above, but only read full instructions when
   > needed"

   That is All-Might's `understanding/_index.md` mechanism, same shape,
   arrived at independently.

2. **HTML-comment markers = the `ALL-MIGHT:BEGIN/END` fence.**
   `MemoryMiddleware` strips HTML comments before injecting memory. The
   docstring says why: so they can hold *"authoring notes or
   **machine-managed markers** without exposing them to the model."*

3. **`memory_guard.py` = marker-gated write protection.** Onboarding
   writes managed content into `AGENTS.md` inside a marker-delimited
   block. Because the same prompt also tells the model to `edit_file`
   that file, a middleware intercepts `write_file`/`edit_file`/`delete`
   on guarded files, **keeps the model's other edits, restores the
   managed block, and returns an error so the model learns the region
   is machine-managed.**

   That is All-Might's fence rule — "only the region between
   `ALL-MIGHT:BEGIN` and `ALL-MIGHT:END` is ours, everything outside
   survives byte-for-byte" — solved the same way by a different team.
   Independent convergence on a rule this specific is strong evidence
   the rule is correct.

### What `dcode` confirmed does *not* have

Grepped all 223 modules for `vector|embedding|semantic search|
InMemoryStore|BaseStore` — **zero hits in any memory or recall path.**

- No vector-indexed journal, no `/recall`, no semantic memory search.
  Long-term memory is markdown-in-system-prompt, full stop.
- No git mirror, no `restore --rev`, no memory version control.
- **No `init` subcommand** — `dcode` does not scaffold a project.

### The direction of the arrow (the decisive insight)

`dcode` reads `.claude/skills/` and `~/.claude/skills/` — but **only as
read-only, experimental skill *input* sources**. It reads `.mcp.json`.
It writes exclusively into its own namespace (`~/.deepagents/`,
`.deepagents/`, `.agents/`). Grep found **zero** occurrences of
`opencode`, `.cursor`, or `CLAUDE.md` as write targets.

> **`deepagents-code` reads the Claude Code convention files so it can
> *replace* Claude Code. All-Might writes them so Claude Code and
> OpenCode behave better.**

LangChain's answer to "I want a good coding agent" is *use ours*, not
*improve yours*. That is a different product, not a competing one — but
it is competing for the same user's attention, and it now ships daily.

## 5. Verdict on the maintainer's hypothesis

**The hypothesis is half right, and it is aimed at the wrong package.**

`langchain` / `langgraph` / `langsmith` — the three named in the
hypothesis — cover approximately **none** of All-Might's goals. They
are an application SDK plus an observability platform. The overlap is
entirely in `deepagents` + `deepagents-code`, which the hypothesis did
not name.

So the honest restatement is not *"already covered"* but:

> **The same design problems are being solved one layer over, by a team
> that decided to replace the CLI rather than configure it.**

With that correction, the rest holds: half right, and the wrong half is
the half that matters.

### Where it is right — capability (`what`)

Everything All-Might does conceptually, the LangChain ecosystem now has,
and mostly more maturely:

| Concern | All-Might | LangChain ecosystem |
|---|---|---|
| Roles with own prompts | `personalities/*/ROLE.md` | `SubAgent(system_prompt=...)` |
| Markdown memory | L1 `MEMORY.md` | `MemoryMiddleware(sources=["AGENTS.md"])` |
| Vector-searched long memory | L3 + SMAK | `Store(query=...)` + `langmem` |
| Periodic reflection | `/reflect` | `ReflectionExecutor` |
| Skills | `.opencode/skills/` | `skills=[...]` → `SkillsMiddleware` |
| Delegation | subagent `@mention` | `task()` tool |
| Self-scoring | — | `RubricMiddleware` |
| Human-in-the-loop | — | `interrupt_on=` |
| Time-travel debugging | — | checkpointer `get_state_history` |

On raw feature coverage All-Might loses. It should stop claiming
otherwise internally.

### Where it is wrong — delivery (`how` / `for whom`)

| | All-Might | LangChain ecosystem |
|---|---|---|
| Deliverable | **a directory** (md/yaml/symlinks/plugins) | **a Python program** |
| Runtime owner | OpenCode / Claude Code (someone else's) | LangGraph (yours to operate) |
| User action | keep using their editor | write, deploy, and maintain an app |
| Memory legibility | `git diff` on a `.md` | JSON in a Store, or a LangSmith trace |
| Recovery | `allmight memory restore` + git log | inspect DB / re-run |
| Air-gap | design goal | core runs offline; LangSmith is cloud |
| Per-role isolation | directory tree (fails closed) | tuple prefix (fails **open**) |

The one-line statement of the difference:

> **deepagents lets you *write* an agent that has roles and memory.
> All-Might gives a user a workspace that *has* roles and memory,
> without them writing any code.**

The target user — a std-cell owner who wants to open OpenCode inside an
EDA project and talk to it — does not become a LangGraph application
developer. If they were willing to, they would not need All-Might, and
they would also not need OpenCode.

### The real strategic risk (not LangChain)

LangChain is not the threat, because it sits at a different layer. The
threat is the **layer below**: if Claude Code or OpenCode ships
`deepagents`-equivalent middleware natively — per-role subagents with
scoped markdown memory, wired from config — All-Might's entire reason
to exist evaporates overnight.

The 2026-08-15 platform recon shows this is already in motion:

- Claude Code now has **auto-memory** at
  `~/.claude/projects/<project>/memory/MEMORY.md` — reportedly using a
  **pointer-index** pattern, i.e. All-Might's L2 `_index.md` TOC
  mechanism, first-party. *(Confidence: architectural claim
  corroborated across sources, timing not verified — must be confirmed
  against Anthropic's own docs.)*
- Claude Code subagents now accept a `skills:` preload field and
  `memory` config.
- Claude Code merged custom commands into skills.

**Recommended posture**: stop competing on *features* (a losing race
against LangChain's headcount) and concentrate on the two things
neither LangChain nor the CLI vendors are doing:

1. **Zero-code delivery** — the user never writes Python. This is the
   moat, and it is the *only* moat.
2. **Recoverability** — git-mirrored, human-diffable memory with
   `allmight memory restore`. LangChain's answer is a LangSmith trace,
   which is cloud, and `InMemoryStore`, which is nothing.

Per-role isolation is a *third* differentiator, but it is weaker than
previously assessed: LangGraph *can* express it via namespaces, it just
does not enforce it. The honest claim is "fails closed vs fails open",
not "we have it and they don't."

## 6. ⚠️ Two real All-Might bugs found (highest-value items in this log)

These came out of the routine platform recon, are **pre-existing**, and
are **not** caused by any upstream change. Neither is catchable by the
current Python string-presence test suite.

### BUG-1 — `PreCompact` hooks silently do nothing on Claude Code

`src/allmight/core/claude_bridge.py:348-356` and
`src/allmight/capabilities/memory/initializer.py:1999-2006` both emit:

```json
{"hookSpecificOutput": {"hookEventName": "PreCompact", "additionalContext": "..."}}
```

Claude Code's hooks documentation (`code.claude.com/docs/en/hooks`)
has **no `hookSpecificOutput` section** for `SessionStart`,
`UserPromptSubmit`, `PreCompact`, or `PostCompact` — only the universal
fields (`continue`, `stopReason`, `suppressOutput`, `systemMessage`)
apply. The documented context path for those events is **plain
stdout**. A schema-invalid object is a *non-blocking* error: the action
proceeds and a `<hook name> hook error` notice appears in the
transcript.

> **Correction (added when writing the proposal).** "Silent" above is
> too strong — there *is* a transcript notice. It is silent to the
> agent's context and to our test suite, which is the part that
> matters, but the log originally overstated it.

Follow-up analysis found a **second, independent defect** that settles
the case without relying on any inference about field handling:
`PreCompact` fires *before* compaction, whereas the OpenCode side
re-primes *after* it (`session.compacted` marks the session un-primed,
the next `chat.message` re-injects). So the two surfaces disagree on
**timing**, not just protocol. Also: `SessionStart` accepts a `compact`
source and we register it with no matcher, so the correct
post-compaction re-prime **already exists** — `PreCompact` is redundant
as well as broken.

Consequence: the Claude Code side of "re-prime `MEMORY.md` + `ROLE.md`
after compaction" — the entire point of that hook registration — is
very likely a **silent no-op**, while the OpenCode side
(`experimental.session.compacting`) works correctly. This is textbook
cross-surface drift, the exact failure mode the *Dual-platform
invariant* section of CLAUDE.md exists to prevent.

**Fix**: drop the `PreCompact` registration entirely (`SessionStart`
already covers the `compact` source) and switch both reload generators
to plain stdout. `PostCompact` was considered and rejected — it has no
documented context-injection path either.

**→ Full proposal: `docs/compaction-reprime-proposal.md`.**

### BUG-2 — 10,000-character cap on hook output, silently truncated

> "Hook output strings, including `additionalContext`, `systemMessage`,
> and plain stdout, are capped at 10,000 characters."
> — `code.claude.com/docs/en/hooks` (verified)

`role_load.py` concatenates **every** personality's full `ROLE.md`; the
memory hook injects all of `MEMORY.md`. A three-personality EDA project
exceeds 10 KB trivially, and the truncation is silent.

The cap applies to **plain stdout too**, so the B1 fix does not rescue
it. Truncation takes the tail, so the alphabetically-last personalities
are the ones that vanish.

**Fix**: a shared `HOOK_OUTPUT_BUDGET` constant plus, when the payload
exceeds it, degradation to a **role index** (name + summary + path,
read-on-demand) rather than a blind `[:10000]` cut — reusing the L2
progressive-disclosure pattern the codebase already commits to.

**→ Full proposal: `docs/compaction-reprime-proposal.md`.**

## 7. Secondary reconnaissance — two repos worth the skip-list

Demoted this pass because the LangChain trial took priority, but both
clear the junk filter on real-issue-traffic grounds.

### `vshulcz/deja-vu` (634★, created 2026-07-14)

Inverts the memory premise: rather than capturing forward, it
**retro-indexes the session stores 17 harnesses already wrote to disk**
(Claude Code, Cursor, Codex, Cline, Gemini CLI, …), including history
predating installation. Single Go binary, no LLM, no embeddings, no
egress. Surface is MCP + CLI (`deja recall`, `deja blame <path>`,
`deja friction`).

> "Memory tools start empty and record forward. deja starts full."

Its issue tracker independently rediscovers three invariants All-Might
already encodes — marker-ownership ("install overwrites a skill the
user edited, because nothing records which copy was ours"), the
capability matrix (`PLUGIN_MANIFEST.requires` / `claude_code_mirror:
None`), and cross-harness duplicate skill discovery (the OMO
`claude-code-hooks` hazard, generalised to 17 harnesses).

**Caveat recorded**: all 12 issues are authored by the maintainer, and
the two "outside" PR authors write in the maintainer's distinctive
style. Treat the community signal as unverified.

**Transferable idea (not yet a proposal)**: `deja friction` — mining
the *existing* transcript corpus for friction points, versus
All-Might's per-turn friction jot which records forward. Worth
comparing against the just-landed evidence-backstop work (commit
`213d9f4`) next pass.

### `mindmuxai/brain.md` (444★, created 2026-06-18)

Repo-native markdown project brain, Apache-2.0, v0.2.0. The design is a
**page** holding two separately-governed regions: a rewritable
**compiled truth** plus an **append-only timeline**, so "changes never
occur without a recorded rationale."

> "Correct by construction — no validator needed because the CLI is the
> only writer."

That sentence is almost verbatim All-Might's own rule ("written
deterministically by Python — never by the agent free-form"). Its other
two principles — *single brain per project*, *pure files, portable* —
map onto "One global slash-command surface" and "No SQLite memory
store."

**Why it is analytically useful**: brain.md gets durability from a
truth/timeline pair **inside one file**, where All-Might splits the same
concern across tiers (L2 `understanding/` = truth, L3 `journal/` =
timeline) and pays a vector index plus a git mirror for it. brain.md is
therefore the **control experiment** for whether L3 + SMAK is
load-bearing. If a single-file truth/timeline pair delivers comparable
recall, All-Might's L3 is over-built. Not actionable yet; a genuinely
falsifiable question for a later pass.

   for agent memory; two independent in-window adopters
   (`thecodacus/understory`, `psinetron/echoes-vault-opencode`). If it
   spreads it becomes the interop target for L2 `understanding/`.
2. **The markdown camp won.** Six passes ago it was a contrarian
   minority call (Serena + All-Might). This pass it is `deepagents`,

## 8. Challenges to All-Might

| # | Challenge | Verdict | Rationale |
|---|---|---|---|
| Q1 | Rebuild All-Might on top of LangGraph / `deepagents`? | **Reject — decisively.** | It inverts the deliverable. All-Might ships a *directory* the user opens in their existing editor; `deepagents` ships a *Python program* the user must operate. Adopting it would require every user to become a LangGraph application developer, which destroys the only moat. |
| Q2 | Adopt `deepagents`' `MemoryMiddleware` prompt as a model for our memory guidance? | **Reject.** | 5,120 chars / ~1,280 tokens **per model call**, non-configurable, non-lazy. It is exactly the meta-cognition anti-pattern the Style Guide rejects on sight, and it is fatal on Haiku-class air-gap deployments. Our 549-char `ROUTING_PREAMBLE` is the correct scale. |
| Q3 | Adopt `RubricMiddleware`-style self-scoring (the one deepagents feature with no All-Might equivalent)? | **Defer — no evidence of need.** | Genuinely novel, but there is no observed failure it would fix. Re-open only if `/reflect` telemetry shows quality drift the current audit misses. |
| Q4 | Use LangGraph `Store` namespaces instead of directories for per-role memory? | **Reject.** | Trial proved isolation is convention-only: `search(("memories",))` returns every role's items. Directories fail closed; tuple prefixes fail open. Also loses `git diff` and `allmight memory restore`. |
| Q5 | Adopt LangSmith for tracing/evals? | **Reject.** | Correction to an earlier assumption: LangSmith is a hard dep of `langchain-core` but is **inert by default** — `utils.tracing_is_enabled()` returns `False`, nothing phones home without `LANGSMITH_TRACING=true` + a key. The blocker is the *platform*: self-hosting is an enterprise SKU, and outside a separately-negotiated air-gap license it requires mandatory egress to `beacon.langchain.com`. `allmight plugin status` heartbeats cover the need at zero external dependency. |
| Q10 | Adopt `deepagents-code`'s `memory_guard` restore-on-edit behaviour for our fenced files? | **Defer — genuinely interesting.** | Today All-Might's fence is enforced only at *write* time by `init`/`compose`. `dcode` additionally guards against the **model** editing the managed region mid-session, restoring the block and returning an error so the model learns. We have no equivalent runtime guard. No observed user pain yet, but this is the first idea this pass that would be a real addition rather than a re-implementation. Re-open if a user reports the agent clobbering a fenced region. |
| Q6 | **Fix BUG-1 (`PreCompact` → `PostCompact`/`SessionStart`)** | **Build now.** | Real, silent, cross-surface regression in shipped code. See §9 rating. |
| Q7 | **Fix BUG-2 (10k truncation budget)** | **Build now.** | Real, silent, and worsens exactly as a project adds personalities — i.e. it hurts the heaviest users most. See §9 rating. |
| Q8 | Add a SKILL.md `name` regex test (P-1)? | **Build — trivial.** | ~5 lines. Prevents a future skill name being silently rejected by OpenCode. |
| Q9 | Retire L3 + SMAK in favour of a brain.md-style truth/timeline single file? | **Reject for now; keep as the open question.** | Genuinely falsifiable and worth answering eventually, but the migration cost is enormous and no user pain is observed. Revisit only with evidence that L3 recall is unused or underperforming. |

## 10. Lessons captured

- **Trying beats reading.** Six passes of paper comparison never
  surfaced the 39× prompt-overhead ratio or the silent `query=`
  degradation. Thirty minutes of `pip install` + three scripts did.
  Where a competitor is installable, install it.
- **Convergence is validation *and* commoditisation.** Markdown memory
  was a contrarian call in May; by August it is what LangChain, brain.md,
  ai-memory, OKF, and Claude Code itself all do. Being right stopped
  being an advantage. Track *when a differentiator becomes table
  stakes*, and move the moat.
- **Feature parity was the wrong scoreboard.** All-Might loses on
  feature count to a team with 100× the headcount and always will. The
  scoreboard that matters is "does the user have to write code?"
- **Fails-closed vs fails-open is a real distinction, and the honest
  version of it is weaker than the marketing version.** LangGraph *can*
  express per-role scoping. It just does not enforce it. Claim the
  enforcement, not the expressiveness.
- **The recon found more value in our own code than in anyone else's.**
  Two shipped, silent bugs beat any feature idea this pass produced.
  Budget future passes accordingly: reading *upstream contracts against
  our own generators* is higher-yield than reading competitors.
- **Star count remains worthless.** A 4★ repo (`two-tier-memory`)
  supplied a sharper thesis than several 1k★ repos; three 500★+ repos
  had literally zero issues.
- **Check the hypothesis's *attribution*, not just its truth value.**
  The maintainer named LangChain/LangGraph/LangSmith. The real overlap
  was in `deepagents-code`, a package the hypothesis never mentioned
  and which shipped a release the day before this pass. Answering the
  question as asked would have produced a confidently wrong "no
  overlap" verdict. When testing a threat hypothesis, enumerate the
  whole dependency tree before concluding.
- **Independent convergence on a *specific* rule is strong evidence
  the rule is right.** Marker-fenced managed regions inside a
  user-shared file, with the model told to edit around them, is a
  narrow and non-obvious design. Two teams reached it separately
  (`ALL-MIGHT:BEGIN/END` and `memory_guard.py`). Broad convergence
  (markdown memory) commoditises a differentiator; *narrow*
  convergence validates a mechanism.
